Merged upstream • October 2026

KDE Connect: unbounded Bluetooth packet buffer on Android

KDE Connect links phones with desktops to share notifications, files and the clipboard. Its Android Bluetooth backend buffered incoming packets with no size limit, so a paired device that never sent a line terminator could make the app run out of memory. Bluetooth support is an opt-in beta. Creator and maintainer Albert Vaca Cintora merged our fix, which reuses the 32 MB limit the LAN backend already had.

💬 "Merged upstream merge request !696 on the same day with automated unit tests." — Albert Vaca Cintora (KDE Connect)
  • 4 Oct 2026. A scan of KDE Connect for Android flagged the unbounded buffer in BluetoothLink.kt; triage rated it valid.
  • 8 Oct. We opened merge request !696 with the fix and a unit test. Albert Vaca Cintora merged it the same day; not in a tagged release yet.

How to read this. The scanner’s triage called the attacker remote; reading the code narrowed it to an opt-in backend and an already paired device. Findings are leads for people, not verdicts.

Merged upstream • October 2026

ProFTPD: keyboard-interactive answers matched to the wrong PAM prompts

ProFTPD is a widely deployed FTP and SFTP server. Its mod_sftp_pam module matched keyboard-interactive answers to PAM prompts by the wrong index. When a PAM module sent an info message before a prompt, as pam-krb5 does during a password change, login failed or the session process read past the end of the answers array. Maintainer TJ Saunders merged our fix.

💬 "Confirmed with ASan test harness and merged fix into master branch." — TJ Saunders (ProFTPD)
  • 30 Sep 2026. A scan of the ProFTPD tree flagged sftppam_converse(); three triage rounds rated it valid.
  • 2 Oct. We confirmed it with an AddressSanitizer harness and opened pull request #2355.
  • 7 Oct. TJ Saunders merged it into master; not in a tagged release yet.
  • Read the full story →
  • Pull request #2355
  • Maintainer reply

How to read this. The scanner’s triage overstated the reach; reading the receiving code narrowed it to PAM stacks that mix messages and prompts. Findings are leads for people, not verdicts.

Released upstream • October 2026

Windmill: unbounded S3 downloads for AI attachments

Windmill is an open-source platform for scripts, workflows and internal tools. When an AI step referenced an S3 object, Windmill downloaded the whole object and base64-encoded it with no size limit, so one large object could exhaust a worker’s memory. Our size check came too late; maintainer Ruben Fiszel replaced it with a bounded download.

💬 "Maintainer merged bounded download upstream in PR #11534, tagged and released in v1.824.0." — Ruben Fiszel (Windmill)
  • 2 Oct 2026. A scan of Windmill’s AI backend flagged the unbounded download in image_handler.rs.
  • 4 Oct. We opened pull request #11515 with a size check before encoding.
  • 5 Oct. Ruben Fiszel merged a bounded download in #11534, released in v1.824.0.

Merged • Shared library hardening • October 2026

Himalaya: terminal escape injection and BiDi spoofing defense in Rust email tables

Himalaya is a popular CLI email client written in Rust. BudgetScan flagged that message metadata (subjects, sender names, attachment filenames) was printed into terminal tables without escaping control characters. An attacker could craft emails with OSC 52 sequences to silently overwrite the user's clipboard, manipulate terminal output, or use Unicode BiDi overrides to disguise executable attachments. Maintainer Clément Douin extracted our sanitization into the shared pimalaya-cli library with co-authorship credit, so its sister CLI tools can adopt it too.

💬 "Moved sanitization into shared pimalaya-cli 0.2.6 with BiDi filtering, crediting Martin Vlach as co-author." — Clément Douin (Himalaya)
  • 2 Oct 2026. BudgetScan flagged unescaped metadata rendering in Himalaya's table output. We opened pull request #771 on GitHub with an initial patch and test suite.
  • 2 Oct. Maintainer Clément Douin (soywod) recognized that sister CLI projects (cardamum, calendula) share the same tables. He moved the sanitization into pimalaya-cli 0.2.6 with BiDi override filtering, crediting Martin Vlach as co-author.
  • 3 Oct. We completed backend coverage across IMAP, JMAP, Gmail, Graph and pimdir backends and added unit tests. Maintainer Douin reviewed and merged pull request #771 into master.
  • 11–12 Oct. Community contributor SORALNV built on PR #771 with PR #782 (atomic attachment downloads, merged) and PR #783 (message view sanitization, approved).
  • Read the full story →

  • Maintainer review & co-authorship note
  • pimalaya-cli crate on crates.io

Fixed in OpenBSD and tmux upstream • October 2026

tmux: server crash on copy-mode -S without attached client

tmux is the ubiquitous terminal multiplexer. When executing its copy-mode -S handler without an attached client (such as from a hook or background server queue), tmux dereferenced a NULL client pointer, crashing that tmux server with SIGSEGV and ending all of its sessions. Creator and lead maintainer Nicholas Marriott accepted our report and applied the fix to OpenBSD CVS.

💬 "Applied to OpenBSD now, will be in GitHub later. Thanks!" — Nicholas Marriott (tmux / OpenBSD)
  • 1 Oct 2026. BudgetScan flagged the unguarded client pointer in cmd-copy-mode.c. We verified the crash path via hooks and opened pull request #5670 on GitHub with the fix and an automated regression test.
  • 2 Oct. tmux lead maintainer Nicholas Marriott (nicm) reviewed the pull request, replied “Applied to OpenBSD now, will be in GitHub later. Thanks!”, and committed revision 1.55 to OpenBSD CVS credited to Martin Vlach. The same day it was synced to tmux on GitHub as commit 5932140.

Fixed upstream • October 2026

dnsmasq: stale SLAAC name records after a DHCP lease loses its hostname

dnsmasq is the DNS and DHCP server built into many routers and Linux systems. A DHCP lease that lost its hostname kept its SLAAC name records, so a later ICMPv6 reply handed a NULL hostname to a log call. We mailed a patch for the log line; author Simon Kelley fixed the underlying stale records instead and credited Martin Vlach in the commit. A second patch from the same scan was applied too.

💬 "Simon Kelley committed broader fix clearing stale records, crediting Martin Vlach in commit 03fd0c1." — Simon Kelley (dnsmasq)
  • 30 Sep 2026. A scan flagged the NULL hostname in slaac_ping_reply(); we mailed a patch to dnsmasq-discuss.
  • 1 Oct. Simon Kelley committed a broader fix that clears stale SLAAC-name data, and also committed our second patch from the same scan, for an allocation-failure bug in poll_listen().
  • 11 Oct. He replied to both patches on the list; neither is in a tagged release yet.

First hit on open source • September 2026

Yopass: unverified emails could pass OIDC domain restrictions

Yopass is an open-source tool (over 3,000 GitHub stars) for securely sharing secrets, passwords and files. When it is set to allow logins only from certain email domains, its OIDC login trusted the email address returned by the identity provider without checking the email_verified claim. Someone with an unverified account at an identity provider under an allowed domain could therefore get past the domain restriction.

💬 "Maintainer Johan Haals built on patch with opt-out warning, keeping our commit with original authorship." — Johan Haals (Yopass)
  • 23 Sep 2026. BudgetScan flagged the missing check. We opened a pull request with a fix and tests.
  • 24 Sep. An automated review asked for stronger tests, which we added. The maintainer pointed out that email_verified is an optional claim, so enforcing it blindly could break existing setups.
  • 25 Sep. Maintainer Johan Haals built on our patch in a new pull request: he kept our commit as the first one, with its authorship, and added an explicit opt-out for providers that omit the claim, a startup warning, configuration validation, tests and documentation.
  • 26 Sep. Merged into Yopass. By default, OIDC logins now require a verified email.
