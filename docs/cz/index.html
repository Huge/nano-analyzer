Zvyšujeme bezpečnost softwaru pro-bono pro open-source ekosystémy a profesionálně pro vývojové týmy. BudgetScan je náš bezpečnostní skener navržený pro hloubkové odhalování zero-day zranitelností s přísnou kontrolou nákladů, odhadem ceny předem a bezproblémovou integrací do CI/CD.

Příkazy kontroly nákladů Interní workflow 🛡️ Ověřené nálezy

Raný přístup. Jádro CLI skeneru a nástroj pro předběžný odhad nákladů (budget.py) fungují dnes. Spouštění komentáři v PR a kreditové balíčky jsou v aktivním vývoji. Postaveno na nano-analyzer.

Odhad nákladů & řízení rozpočtu

Zjistěte přesnou cenu skenu předem, než utratíte jediný cent, a nastavte tvrdé rozpočtové i časové stropy pro CI.

Krok 1 • Odhad předem $0.00 Zdarma

Modelujte náklady před spuštěním

Nástroj budget.py prozkoumá skenovatelný kód, odfiltruje testy a závislosti a spočítá tokenové náklady napříč modely (Claude, Qwen, DeepSeek, Gemini, Mistral) při 3 i 5 kolech: 

# Prozkoumání kódu & kalkulace nákladů na tokeny:
uv run budget.py /path/to/repo
Krok 2 • Jádro CLI / CI Připraveno

Tvrdé stropy na rozpočet i čas běhu

Skener nikdy nepřekročí zadaný dolarový rozpočet ani neblokuje CI pipeline. Po uplynutí časového limitu bezpečně vyexportuje částečný nálezový report: 

# Audit se stropem $5.00 a maximální dobou běhu 5 minut:
uv run scan.py /path/to/repo \
  --max-budget 5.00 --max-delay 5m --rounds 3 --db scan.db
Krok 3 • Bot v PR komentářích Ve vývoji

Spouštění přímo z Merge Requestu

Vývojáři a revieweři řídí hloubku auditu přímo v komentáři; z týmového kreditního fondu se odečte pouze skutečně spotřebovaná částka: 

# Komentář v GitLab MR nebo GitHub PR:

Interní workflow & Open-Source původ

BudgetScan staví na open-source skeneru nano-analyzer od AISLE (Apache-2.0, představeném na jejich blogu). Zde je původní architektura a přehled toho, jak jsme ji rozšířili na produkční systém řízení rozpočtu.

Původní schéma nano-analyzer: Rozklad zdrojového repozitáře → chunking → volání modelu → filtr triáže → markdown report.

Co jsme postavili nad původním open-source jádrem

💰 Předběžný odhad nákladů (`budget.py`)

Přesně spočítá znaky AST kódu, vstupní a výstupní tokeny pro 7 špičkových modelů a odhadne celkové náklady ještě před spuštěním skenu.

⚖️ Běhový Budget Governor (`--max-budget`)

Vynucuje pevný dolarový strop. Skener nikdy nepřekročí zadaný rozpočet a podrobně ukládá tokenovou spotřebu do SQLite databáze.

⏱️ Vynucení časového limitu (`--max-delay`)

Předchází timeoutům v CI pipeline sledováním reálného času běhu a včasným vygenerováním částečného reportu s pokrytými soubory.

🔍 Vícekolová oponentní triáž (Kola 0–5)

Rozšiřuje jednokolový filtr o vícekolovou skeptickou křížovou oponenturu, která eliminuje plané poplachy na minimum.

⚡ Tree-Sitter AST & Hashovací cache

Funkce a třídy jsou hashovány v SQLite. Nezměněný kód mezi commity se přeskakuje, takže za identickou logiku nikdy neplatíte dvakrát.

🛡️ Nativní CI/CD & SARIF 2.1.0 Export

Kompletní integrace do GitLab CI (`.gitlab-ci.yml`) i GitHub Actions (`action.yml`) s přímým nahráváním do bezpečnostních záložek.

Integrace do libovolné pipeline za 60 sekund

Žádný vendor lock-in. BudgetScan běží všude, kde běží Python a Git, a exportuje standardní SARIF 2.1.0 přímo do vaší bezpečnostní záložky.

# .gitlab-ci.yml: Bezpečnostní audit s rozpočtovým stropem při každém MR
stages:
  - security

budgetscan:
  stage: security
  image: python:3.13-slim
  script:
    - pip install uv && uv sync
    - uv run scan.py . --max-budget 5.00 --rounds 3 --db scan.db
    - uv run python -m web.dashboard.export --format sarif --output gl-sast-report.sarif
  artifacts:
    reports:
      sast: gl-sast-report.sarif
    paths:
      - scan.db
# .github/workflows/security.yml: Přímý upload do záložky GitHub Security
name: BudgetScan Security Audit
on: [push, pull_request]

jobs:
  audit:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - name: Run BudgetScan
        run: uv run scan.py ./src --rounds 3 --max-budget 5.00 --db ./scan.db
      - name: Upload SARIF to GitHub Code Scanning
        uses: github/codeql-action/upload-sarif@v3
        with:
          sarif_file: scan-report.sarif
# Rychlý vývojářský audit s pevným stropem $2.50 a 3 koly triáže:
uv run scan.py /path/to/repo --rounds 3 --max-budget 2.50 --db ./scan.db

# Nebo odhadněte cenu skenu předem, než utratíte jediný cent:
uv run budget.py /path/to/repo

Proč platit za sken, a ne za licenci

Platíte pouze za skutečně zkontrolovaný kód, s přesnými stropy na rozpočet i termín.

Kontrola Rozpočtu

Budget Governor na každý sken

Žádné poplatky za neaktivní vývojáře. Určete cenový a časový strop na PR (--max-budget, --max-delay). Selhané skeny nikdy neúčtujeme.

Přesnost

Skeptická vícekolová triáž

AI skenery generují šum, pokud nejsou korigovány. Nálezy střední a vyšší závažnosti procházejí křížovou oponenturou, která eliminuje plané poplachy.

Efektivita a Soukromí

AST Cache a nulová retence

Hashování funkcí přeskakuje nezměněný kód, takže za stejné funkce neplatíte dvakrát. Kód putuje pouze k vybranému LLM partnerovi (EU bez retence dat, nebo on-premise).

Vícekolová filtrace nálezů

Každé podezření prochází několika koly oponentury, než je nahlášeno vývojářům:

Kolo 0
Rychlý sběr podezření
Kolo 1
Syntaktická filtrace
Kolo 2
Kontext celého souboru
Kolo 3
Ověření dosažitelnosti
Finální triage
Ověřené nálezy s PoC testem
