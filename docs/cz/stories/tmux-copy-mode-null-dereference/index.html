Začleněno do OpenBSD 2. 10. 2026  Oprava chyby v tmuxu v upstreamu

tmux: pád serveru při copy-mode -S bez připojeného klienta

BudgetScan odhalil chybějící kontrolu NULL ukazatele v obsluze copy-mode -S v tmuxu, celosvětově používaném terminálovém multiplexeru. Při vyvolání v kontextu serveru bez připojeného terminálového klienta (například z hooků nebo front příkazů na pozadí) vedla chybějící kontrola k okamžitému pádu centrálního serveru tmux na SIGSEGV, což ukončilo všechny běžící relace a procesy všech uživatelů. Nicholas Marriott, autor a hlavní správce tmuxu, přijal naši zprávu a začlenil opravu přímo do CVS OpenBSD.

Co bylo špatně

Příkaz copy-mode nabízí přepínač -S pro posouvání historie pomocí událostí posuvníku myši. Při provádění funkce cmd_copy_mode_exec() získává tmux odkaz na aktivního klienta příkazu voláním cmdq_get_client(item).

Pokud příkaz spustí interaktivní terminálový klient, ukazuje c na strukturu klienta a jeho terminál (c->tty). Příkazy v tmuxu však mohou být vyvolány také na úrovni serveru zcela bez připojeného terminálu — například z konfiguračního souboru ~/.tmux.conf, přes automatizaci na pozadí nebo ze systémových hooků jako pane-died (set-hook -g pane-died "copy-mode -S").

V těchto situacích bez klienta je c rovno NULL. Zatímco sousední větev pro myš (-M) tento stav správně ošetřila:

if (c == NULL || c->session != s)
    return (CMD_RETURN_NORMAL);

ve větvi -S tato kontrola zcela chyběla. Kód okamžitě předal &c->tty do funkce tty_window_offset(), což vedlo k okamžitému pádu na neplatnou paměť (SIGSEGV). Protože tmux běží jako jediný centrální serverový démon obsluhující všechny relace a okna na stroji, pád démona okamžitě usmrtil všechna okna, panely i běžící procesy pro všechny připojené uživatele.

Přiložený regresní test (regress/copy-mode-no-client-scroll.sh) vyvolá copy-mode -S z hooku pane-died bez připojeného klienta. Na původním kódu test okamžitě reprodukoval segmentation fault; s nasazenou opravou server příkaz bezpečně ignoroval a test doběhl zelený.

Správce Nicholas Marriott opravu přijal a začlenil revizi 1.55 přímo do stromu OpenBSD:

„Applied to OpenBSD now, will be in GitHub later. Thanks! 🚀“

Časová osa

  • 1. 10. 2026. BudgetScan upozornil na nechráněný ukazatel na klienta v cmd-copy-mode.c. Manuální audit zdrojového kódu potvrdil vektor pádu serveru přes hooky. Otevřeli jsme pull request #5670 s opravou a regresním testem.
  • 2. 10. (12:12 UTC). Autor a hlavní správce tmuxu Nicholas Marriott (nicm) pull request zhodnotil, odpověděl na GitHubu a začlenil revizi 1.55 do CVS OpenBSD: „Do not use client for copy-mode -S if NULL, reported by Martin Vlach.“

Jak to číst

Skener poukázal na nechráněný ukazatel jako na konkrétní podnět. Inženýr prověřil řídicí tok, izoloval spuštění přes hooky, napsal reprodukovatelný test a připravil opravu. Upstreamový správce Nicholas Marriott ji zvalidoval a začlenil do OpenBSD. Přesně tak má automatizované skenování fungovat: nálezy slouží lidem k prověření, nikoli jako nezpochybnitelné ortely. Velké díky patří Nicholasi Marriottovi za okamžitou, vstřícnou reakci a bezproblémové začlenění do OpenBSD.
